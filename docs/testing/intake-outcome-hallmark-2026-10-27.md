# 문의·결과 Hallmark 개선 검증 — 2026-10-27

## 변경

- 문의 원문 위에 AI 분석 이동 동작을 배치했다. 기존 이동 핸들러와 원문·문서·확정 버전 기능을 유지한다.
- 문의 수동 정리의 기능·설명·우선순위·완료 기준·가정·질문을 탭의 세션 저장소에 보관한다. 편집 닫기·단계 이동·새로고침 후 이어 쓸 수 있으며 저장 성공 또는 확인 후 초안 버리기 때 제거한다.
- 초안 키는 사용자·작업 공간·프로젝트별로 인코딩하고 저장 버전·형태·7일 유효 기간을 검사한다. 저장소를 사용할 수 없으면 화면에 안내하며 확정 저장과 구분한다.
- 문의·결과도 기존 Hallmark 작업 화면 범위에 포함했다. Pretendard·보라색·테마 토큰·앱 셸·공통 단계 탐색을 유지한다.
- 결과 본문을 한 열로 정리하고 기본 입력은 두 열, 모바일은 한 열로 배치했다. 중첩 패널 여백과 테두리를 줄이고 라벨·단위는 14px, 입력은 16px로 맞췄다.
- 결과 조회 실패는 재시도 화면으로 구분하며 결과를 확인하기 전에는 작성 폼을 표시하지 않는다. 연결된 견적 상세만 실패한 경우에는 읽어 온 결과·견적 참조·작업 항목을 유지한다.

## 검증

- `npm run ci:check`: 타입 검사·기본 테스트 596개·ESLint 통과.
- `npm run build`: 운영 모드 빌드 통과. 검사용 API 주소는 localhost이며 외부 AI를 호출하지 않는다.
- `intake-outcome.spec.mjs`: 320·375·390·768·1024·1280·1440·1920px의 한국어/어두운 테마와 영문/밝은 테마에서 문의 동작의 첫 화면 접근, 입력 컨트롤의 가로 넘침, 결과 라벨·단위 14px 이상을 검사한다.
- 기능 시나리오는 문의 초안의 접기·단계 이동·새로고침 복원, 확정 저장 요청의 정확한 필드, 저장 후 초안 제거, 초안 폐기 취소·확인, 프로젝트별 격리, 잘못된 저장 자료, 결과 조회 실패·대기·재시도 복원, 기존 결과 값 저장, 읽기 전용 권한을 다룬다.
- 기존 `project-step-shell.spec.mjs`와 `quotation-pagination.spec.mjs`를 함께 실행해 네 단계 탐색·프로젝트 권한·견적 페이지 및 입력 보존을 확인한다.
- 새 묶음을 Frontend CI의 합성 Chromium 검사 목록에 추가했다. 운영 데이터 변경 없이 서버 응답을 대역으로 제공하고 외부 통신을 차단한다.
- Hallmark의 정적 `--scope app --render --kept` 검사: FAIL 0, REFLEX 0, WARN 0. 필드 8/8 유지. 초안을 초기화하던 편집 토글 핸들러 하나는 사용자 요청에 따른 동작 변경으로 CSS stamp에 기록했다. 접기·다시 열기 기능 자체는 유지하며 브라우저로 검사한다.

## 코드·보안 검토

- API 경로·서버 권한·확정 저장 계약을 바꾸지 않았다. 문의 저장의 쓰기 권한 검사와 저장 중 입력 잠금을 보완했다.
- 초안에 인증 정보는 저장하지 않으며 사용자·작업 공간·프로젝트를 키에서 분리한다. 복원된 문자열은 React의 텍스트·입력 값으로만 표시한다.
- 결과 조회 실패에서 저장 동작을 노출하지 않는다. 결과와 선택적 견적 조회의 오류를 구분해 정상 결과를 숨기지 않는다.
- 스타일은 기존 `.figma-workspace .hallmark-workbench` 안에 한정한다. 소개·인증·설정 화면의 스타일은 변경하지 않는다.
