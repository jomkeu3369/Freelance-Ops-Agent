# 펫과 함께하는 견적 작성 검증 — 2026-10-19

기준 main은 `d561065`다. 펫 선택부터 견적 발행·고객 응답까지 연결되는 화면을 점검했다. 아래 브라우저 결과는 합성 HTTP 응답을 사용하며 실제 DB·모델 호출과 구분한다.

## 수정한 흐름

- AI 분석 화면의 **함께할 펫**에서 선택·편집하고 **펫과 견적 만들기**로 전체 `PROJECT_ANALYSIS`를 시작한다. 일반 대화는 `AD_HOC`를 유지한다.
- 전체 분석에는 저장된 프로젝트 원문과 선택한 스킬·모델을 사용한다. 별도로 작성 중인 대화 초안을 견적 원문으로 바꾸거나 자동 전송하지 않는다.
- 시작 응답을 확인하지 못한 요청은 같은 본문과 멱등키로 명시적으로 재시도한다. 실행·사용자 답변 대기 중에는 펫 변경과 새 견적 실행을 잠근다.
- 펫 설정을 모델·스킬 설정에서 분리했다. 입력→미리보기→저장→선택의 포커스를 연결하고, 사용 안내는 접힌 영역에 둔다.
- 시작 버튼 문구가 헤더의 공통 색상 규칙에 가려지던 문제를 수정했다. 렌더된 문구와 배경의 대비가 4.5:1 이상인지 검사한다.
- 여러 부서의 긴 요약을 합칠 때 공개 `projectSummary`만 10,000자 안으로 줄인다. 부서 원문과 견적 초안은 보존한다. 정상 완료와 부분 실패를 모두 검사한다.

## 로컬 검증 결과

Node.js 22.23.3, Next.js 16.3.8, Chrome과 Python 3.12를 사용했다. 최종 화면 검사는 `next build`·`next start`에서 작업자 하나로 실행했다.

| 프런트엔드 ESLint | 통과 — 기존 로컬 보관 파일을 제외한 앱 코드 범위 |

새 `pet-quotation-workflow.spec.mjs`의 네 시나리오는 다음을 확인한다.

1. 1440px와 390px에서 고객 등록→고객과 연결한 프로젝트→펫 선택→전체 분석→추가 질문 답변→견적 단가 검토→초안 저장→발행→공유→로그인 없는 고객 승인.
2. 견적 저장 실패 후 입력 보존과 명시적 재시도. 저장 전 발행·공유 및 미저장 수정본 발행 차단.
3. 시작 응답 유실 후 같은 키·원문·스킬로 재시도. 작성 중인 대화 초안 보존.

관련 회귀에는 펫 생성·선택·보관·삭제, 세션 격리, SSE 재개, BYOK 실패, 모델 변경, 짧은 화면, 견적 페이지와 브라우저 뒤로/앞으로 이동도 포함한다. 기존 영문 사용량 테스트는 현재 USD 비율 화면에 맞췄고, 단계 이동 검사는 주소 전환을 기다린 뒤 뒤로가기를 실행한다. 개발 모드에서 초기 조회 횟수가 달랐던 컴패니언 검사도 프로덕션에서 기존 기대를 유지한 채 통과했다.

Agent 검증 범위는 `tests/runtime/test_executor.py`, `tests/test_custom_pet_preferences.py`, `tests/test_pet_perspectives.py`, `tests/runtime/test_resume_state_transition.py`다. Windows에서는 pytest 플러그인 자동 로드를 끄고 `-p pytest_asyncio.plugin`을 명시해 실행했다.

## 근거와 재실행

새 브라우저 시나리오는 Frontend CI의 합성 Chromium 검사에 포함한다. 화면 캡처는 `frontend/outputs/pet-readiness/screenshots/`에 생성하며 CI의 `synthetic-browser-reports` artifact에 함께 보관한다. 파일명의 `1440`·`390`은 화면 너비이고 `analysis-ready`·`pet-selection`·`quote-review`는 촬영 단계다. 합성 고객 이름과 `.invalid` 이메일을 사용한다.

프런트엔드의 기존 타입·단위·린트·빌드 명령은 [Frontend README](../../frontend/README.md)를 따른다. 프로덕션 서버가 준비된 상태에서 새 흐름만 다시 검사할 수 있다.

```bash
cd frontend
npx playwright test tests/browser/pet-quotation-workflow.spec.mjs --workers=1
```

## 검증 경계와 촬영 전 확인

인증은 테스트 세션으로 시작하고 업무·AI API 응답을 모의 처리했다. 실제 회원가입·이메일 인증, Spring과 PostgreSQL 영속화, 제공사 접근 권한·모델 응답 품질·실제 비용 정산·메일 전달·운영 배포는 위 77개 화면 검사의 성공 근거가 아니다. Backend 5종 단위검사는 로컬 실행이 완료되지 않아 통과 수에 포함하지 않는다. DB 통합 검증은 PR의 서비스 CI 결과로 별도 확인한다.

이 PR을 실제 서비스에 반영한 뒤 촬영 계정에서 선택한 모델과 예산·개인 키 상태를 확인하고 실제 견적 작성 한 건을 점검해야 운영 화면의 촬영 준비를 확정할 수 있다. 합성 시나리오 캡처를 사용하면 합성 데모임을 표시한다.
