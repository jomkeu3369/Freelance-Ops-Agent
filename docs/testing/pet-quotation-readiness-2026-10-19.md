# 펫과 함께하는 견적 작성 검증 — 2026-10-19

기준 main은 `d561065`다. 펫 선택부터 견적 발행·고객 응답까지 연결되는 화면을 점검했다. 아래 브라우저 결과는 합성 HTTP 응답을 사용하며 실제 DB·모델 호출과 구분한다.

## 수정한 흐름

- AI 분석 화면의 **함께할 펫**에서 선택·편집하고 **펫과 견적 만들기**로 전체 `PROJECT_ANALYSIS`를 시작한다. 일반 대화는 `AD_HOC`를 유지한다.
- 전체 분석에는 저장된 프로젝트 원문과 선택한 스킬·모델을 사용한다. 별도로 작성 중인 대화 초안을 견적 원문으로 바꾸거나 자동 전송하지 않는다.
- 시작 응답을 확인하지 못한 요청은 같은 본문과 멱등키로 명시적으로 재시도한다. 실행·사용자 답변 대기 중에는 펫 변경과 새 견적 실행을 잠근다.
- 펫 변경 요청과 후속 목록 확인이 끝날 때까지 견적·대화 실행을 막는다. 패널을 닫거나 단계를 이동해도 사용자·워크스페이스별 상태를 유지하며, 변경 실패 후에는 명시적인 재선택 성공으로 복구한다.
- 펫 설정을 모델·스킬 설정에서 분리했다. 입력→미리보기→저장→선택의 포커스를 연결하고, 사용 안내는 접힌 영역에 둔다.
- 시작 버튼 문구가 헤더의 공통 색상 규칙에 가려지던 문제를 수정했다. 렌더된 문구와 배경의 대비가 4.5:1 이상인지 검사한다.
- 여러 부서의 긴 요약을 합칠 때 공개 `projectSummary`만 10,000자 안으로 줄인다. 부서 원문과 견적 초안은 보존한다. 정상 완료와 부분 실패를 모두 검사한다.

## 검증 경계와 촬영 전 확인

인증은 테스트 세션으로 시작하고 업무·AI API 응답을 모의 처리했다. 실제 회원가입·이메일 인증, Spring과 PostgreSQL 영속화, 제공사 접근 권한·모델 응답 품질·실제 비용 정산·메일 전달·운영 배포는 위 79개 화면 검사의 성공 근거가 아니다. Backend 5종 단위검사는 로컬 실행이 완료되지 않아 통과 수에 포함하지 않는다. DB 통합 검증은 PR의 서비스 CI 결과로 별도 확인한다.

이 PR을 실제 서비스에 반영한 뒤 촬영 계정에서 선택한 모델과 예산·개인 키 상태를 확인하고 실제 견적 작성 한 건을 점검해야 운영 화면의 촬영 준비를 확정할 수 있다. 합성 시나리오 캡처를 사용하면 합성 데모임을 표시한다.

## 운영 검증에서 발견한 입력 한도 문제

PR #83을 `d40aea97c7b51d785e151e0c75f92d586b791985`로 병합한 뒤 프런트엔드·Agent·Backend 배포 성공과 Backend 준비 상태를 확인했다. 명시적 승인에 따라 기본 제공 AI를 활성화했으며 계정 주 $1.25, 서비스 일 $25·주 $100, `gpt-6-luna` 실행당 $0.10 상한은 유지했다. 촬영은 진행하지 않았다.

로그인된 운영 브라우저에서 새 가상 프로젝트의 원문 445자와 펫 ‘견적냥’을 생성·저장·선택하고 `PROJECT_ANALYSIS`를 한 번 실행했다. 요구사항과 자료 조사 부서는 완료했으나, 견적 구성 부서의 세 번째 호출 전에 `INPUT_TOKEN_BUDGET_EXCEEDED`로 실패했다. 실제 사용량은 8회 호출·입력 25,942·출력 5,797토큰, 정산 비용은 $0.00614067이었다. 실행 종료와 예약 잔액 $0을 운영 원장으로 확인했다. 이 결과를 정상 견적 생성·저장 성공으로 취급하지 않는다.

호출 전 검사는 이미 사용한 입력에 다음 요청 전체의 UTF-8 바이트 크기와 프로토콜 여유분 8,192를 더한다. 네 부서 분석에는 기존 입력 한도 50,000개가 부족했다. 수정은 전체 견적 분석 요청만 100,000개로 맞추고 Backend 운영 정책·Compose 기본값을 일치시키며, 구조화 요청의 JSON 공백과 스키마 설명을 줄인다. 일반 대화 50,000개와 개인 키 150,000개, 호출·출력·시간 제한, 보수적 입력 예약 및 USD 승인 검사는 유지한다. 종료 상태가 확인됐는데도 마지막 진행 이벤트 때문에 ‘분석 중’으로 표시되던 안내도 종료 상태를 우선하도록 수정한다.

운영 `.env`에 남아 있는 명시적 50,000 설정은 별도 반영이 필요하다. 수정된 릴리스의 실제 전체 분석·견적 저장과 비용 정산을 다시 확인하기 전까지 촬영 준비 완료로 판정하지 않는다. 실패 기록은 보존하고 새 검증에는 새 실행과 멱등키를 사용한다.

후속 수정의 로컬 검증은 Agent 플랫폼 예산·제공사·개인 키 회귀 165개, Compose 5개 검사(설정 해석 6회), 프런트엔드 변경부 관련 고유 단위 검사 24개와 변경 앱 파일 ESLint·Python Ruff다. 전체 프런트엔드 실행에서는 510개 중 509개가 통과했고, 이전 입력 한도 분기만 허용하던 소스 검사를 갱신해 해당 검사와 공유 계약을 다시 확인했다. 최종 프런트엔드 전체·실제 브라우저 회귀·Backend 검사는 PR CI에서 확인한다. Windows 샌드박스의 asyncio 내부 소켓 생성 제한 때문에 Agent 검사는 샌드박스 밖에서 외부 공급자를 모의 처리해 실행했다. Docker 데몬·새 유료 AI 호출은 사용하지 않았다.
