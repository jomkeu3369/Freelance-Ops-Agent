# 프론트엔드 실제 서버 통합 검증

## 환경과 범위

- 로컬 Docker 개발 환경: Spring Boot, FastAPI Agent, PostgreSQL/pgvector
- Next.js 화면: `http://localhost:3000`
- 실제 Spring API: `http://localhost:8080`
- 프론트 검증 런타임: Node 22.23.2
- 별도 가상 계정과 `Integration-` 접두어의 작업 공간에서 검증하며 기존 프로젝트는 수정하지 않는다.

## 통합 수정

보드의 단계 변경이 프로젝트 전체 내용을 PATCH하던 동작을 변경했다. 이제 `PATCH /api/v2/workspaces/{workspaceId}/projects/{projectId}/status`에 `{ "status": "QUOTING" }`처럼 단계만 보낸다. 서버는 권한과 작업 공간을 확인하고 최신 프로젝트를 잠근 뒤 단계만 갱신한다. 오래된 화면에서 단계 변경을 하더라도 다른 사용자가 수정한 제목·원문·예산을 덮어쓰지 않는다.

공개 제안서 항목의 타입에서 서버가 노출하지 않는 `rateCardId`를 제외했다. 고객 승인·수정 요청·거절은 기존 사양에 따라 결정 기록으로 저장하며 프로젝트 자동 상태 전이는 추가하지 않았다.

공개 제안서의 중복 응답 오류가 인증 오류로 바뀌는 문제를 수정했다. 서버 내부 ERROR dispatch의 `/error` 경로만 허용하고 직접 접근 및 비공개 API의 인증은 유지한다. 화면에서는 이미 응답이 기록되었다고 안내하고 재전송을 막는다.

Agent의 비관리자 실행 중 uv 캐시 권한 오류를 해결했다. 설치된 의존성을 재사용하고 실행 캐시는 `/tmp/uv-cache`에 둔다. 이 PC의 비어 있던 서비스 간 인증 키는 로컬 키 쌍으로 구성했다. 키는 git에서 제외된 루트 `.env`에만 보존하며, 다른 PC에서는 해당 환경의 키를 구성해야 한다.

AI 초안 안내는 등록 단가가 없는 경우에도 자동 연결되었다고 단정하지 않도록 수정했다.

새 프론트는 단계 전용 API를 사용하므로 다른 환경에 반영할 때 **백엔드를 먼저 업데이트**해야 한다.

## 반복 실행

실제 로컬 서버가 준비된 뒤 `frontend`에서 실행한다.

```powershell
npm ci
node scripts/integration-smoke.mjs
```

검사는 애플리케이션의 `app/lib/api.ts`를 임시로 변환하여 그대로 사용한다. 별도의 가짜 API 구현을 사용하지 않는다. 기본 주소는 `http://localhost:8080`이며 `INTEGRATION_API_BASE_URL`로 다른 loopback 포트를 지정할 수 있다. 운영 주소에는 테스트 계정을 만들지 않도록 loopback 이외의 주소를 거부한다.

기본 실행은 생성한 공유 링크를 취소하고 테스트 프로젝트를 삭제한다. 계정·작업 공간·단가·고객은 로컬의 가상 작업 공간에 남는다. 브라우저 확인용으로 `INTEGRATION_STATE_PATH`를 지정하면 테스트 자료와 로그인 정보를 해당 파일에 보존하므로 검증 후 링크·프로젝트·파일을 정리해야 한다. 로그인 정보 파일을 저장소에 커밋하지 않는다.

브라우저 실행은 `NEXT_PUBLIC_API_BASE_URL=http://localhost:8080`으로 설정한다. 실제 휴대폰 또는 다른 PC에서 접속하려면 API 주소를 그 기기에서 접근 가능한 개발 서버 주소로 바꾸고 `APP_CORS_ALLOWED_ORIGINS`에 프론트 주소를 추가해야 한다. 기기의 `localhost`는 개발 PC를 가리키지 않는다.

## 결과

- 프론트 최종 `preview:check` 통과: 타입 검사, 45개 테스트, 린트, 프로덕션 빌드.
- 백엔드 대상 회귀 검사 통과: 프로젝트 서비스 8개, 단계 API 보안 3개, 인증·오류 처리 보안 5개. 마지막 보안 8개 재실행은 실패·오류·건너뜀 0개다. 실제 보안 필터 체인에서 ERROR `/error`는 409를 유지하고 ERROR `/api/v2/me`는 401로 차단함을 확인했다.
- 실제 PostgreSQL 기반 검사 통과: 가입·인증, 문의 등록·검색, 단계 변경 시 최신 제목 보존, 요구사항 저장, 단가·견적 계산, 견적 발행, 공개 제안서 승인 기록, 중복 응답 409, 결과 저장.
- 실제 브라우저 확인: 로그인·빠른 문의 등록, Agent 실시간 이벤트, 추가 질문 3개 답변, 재개 후 `COMPLETED`, 분석 결과에서 핵심·권장·확장 견적 비교로 이동.
- 검수 작업 공간에는 단가를 등록하지 않아 AI 견적 금액은 0원으로 표시되고 저장이 차단됨을 확인했다. 단가를 등록한 별도 API 검사에서는 8시간 × 50,000원 + 부가세 10% = 440,000원을 확인했다.
- 공개 제안서의 중복 응답 안내와 제출 비활성화를 확인했다. 390px 브라우저 너비에서 공개 제안서의 가로 넘침은 없었다. 실제 휴대폰에서의 검증은 수행하지 않았다.
- 검수 프로젝트와 공유 링크를 삭제하고 사용한 로그인 세션을 종료했다. 가상 계정·작업 공간·고객·단가는 로컬에 남으며 기존 사용자 자료는 변경하지 않았다.
- Docker의 backend·agent·postgres가 모두 healthy 상태임을 확인했다. 기존 개발 서비스를 유지하며 운영 배포·커밋·푸시는 하지 않았다.
- 최종 검증 후 임시 Node 실행 환경, 검수 로그인 정보·로그, Next/Gradle 캐시와 생성 빌드 결과를 제거했다. 로컬 인증 키가 설정된 `.env`와 기존 서비스 데이터는 유지한다.
