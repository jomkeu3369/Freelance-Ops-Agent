# ADR-0030: 제한된 AI 펫 관점과 사용자 검토 후 견적 반영

- 상태: Accepted
- 결정일: 2026-09-12
- 근거: 사용자가 AI 펫 작업 공간 제안의 계획 수립·구현을 요청함

## Context

사용자는 작은 동료들이 작업하고 서로 다른 의견을 제시하는 경험을 원한다. 기존 Supervisor는 이미 제한된 실행과 세 견적안을 제공한다. 캐릭터마다 전체 실행을 복제하면 비용·지연과 근거 불일치가 증가한다. 기존 견적 화면의 브라우저 합계는 위험 대비 금액·최소 단가 정책을 모두 반영하는 최종 서버 계산과 다를 수 있다.

## Decision

- 초기 펫은 일정 거북이(핵심안), 근거 부엉이(권장안), 수익 고양이(확장안) 세 관점을 담당한다. 성향은 우선순위이며 해당 안이 무조건 더 좋거나 수익을 보장한다는 뜻이 아니다.
- 기존 Agent 실행에서 견적안별 공개 제안·판단 이유·트레이드오프를 구조화해 반환한다. 펫은 독립 실행 세 개를 가장하지 않는다. 추가 모델 호출·임의 토론 loop 없이 기존 budget을 따른다.
- 기존 실행의 없는 의견은 역할 소개로 대신하지 않는다. 하위 호환을 위해 의견은 선택 필드로 추가하며 이전 실행은 기존 견적안 비교로 안내한다.
- 실행 상태 표현은 Spring의 run status/activeDepartment/result와 일치시킨다. 완료되지 않은 작업을 완료로, 실패를 성공으로 표시하지 않는다.
- 변경 미리보기는 Spring의 기존 견적 계산·단가·근거·정책 검증을 재사용하고 저장하지 않는다. 사용자의 명시적 적용은 편집 초안을 변경하며 저장·발행은 기존 권한과 revision 흐름을 거친다.
- 조합 시 항목·근거와 원래 제안을 함께 검토한다. 모델 텍스트는 실행 명령이나 권한으로 해석하지 않는다.
- ADR-0010/시각 기준의 절제된 업무 표현에 펫 영역만 예외를 추가한다. 질문과 결과를 가리지 않고 접기·키보드·모바일·동작 줄이기를 지원한다.
- BYOK와 생성 외형은 별도 자격 증명·자산 계약이 필요하며 이 ADR은 저장 방식을 승인하지 않는다.

## Consequences

기존 런타임·예산·감사·revision을 재사용하면서 펫의 의견을 실제 결과와 연결할 수 있다. 초기에는 고정 세 관점이고 사용자가 임의 성향을 만드는 기능과 짧은 반론은 후속 계약이 필요하다. 모델이 새 의견 필드를 생성하지 못하면 없는 의견을 합성하지 않고 기존 비교를 유지한다.
