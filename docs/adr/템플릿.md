다른 PC에서는 **저장소를 최신 상태로 받은 뒤, Codex에게 `AGENTS.md → V2 명세 → STATUS → ADR` 순서로 읽고 이어서 작업하라고 명령**하면 됩니다.

Codex 대화 자체를 전달할 필요는 없습니다. Git에 기록된 문서가 대화의 역할을 대신합니다.

## 1. 기존 PC에서 작업을 끝낼 때

Codex에 다음 명령을 전달하세요.

```text
현재 작업을 종료할 준비를 해주세요.

1. AGENTS.md의 작업 종료 절차를 따르세요.
2. 변경 범위에 맞는 테스트와 정적 검사를 실행하세요.
3. git diff와 git status를 확인하세요.
4. docs/STATUS.md에 다음 내용을 갱신하세요.
   - 완료한 작업
   - 현재 진행 중인 작업
   - 다음 작업
   - 실행한 테스트와 결과
   - blocker
5. 민감 정보가 포함되지 않았는지 검사하세요.
6. 아직 commit이나 push는 하지 마세요.
7. 마지막에 변경 파일과 권장 commit 메시지를 알려주세요.
```

결과를 확인한 후 commit과 push를 요청합니다.

```text
확인했습니다. 현재 작업과 관련된 파일만 stage하고,
권장한 메시지로 commit한 뒤 현재 branch를 origin에 push해 주세요.
```

또는 직접 실행할 수 있습니다.

```powershell
git status --short
git add <관련-파일>
git commit -m "docs: establish V2 architecture handoff"
git push -u origin <현재-브랜치>
```

`git stash`는 다른 PC로 전달되지 않으므로 기기를 이동하기 전에 반드시 commit과 push가 필요합니다.

## 2. 처음 사용하는 PC에서 저장소 준비

저장소가 없다면:

```powershell
git clone https://github.com/jomkeu3369/Freelance-Ops-Agent.git
cd Freelance-Ops-Agent
git fetch origin
```

이미 clone되어 있다면 먼저 작업 중인 로컬 변경이 없는지 확인합니다.

```powershell
git status --short
git fetch origin
```

원격 branch를 처음 받는 경우:

```powershell
git switch --track origin/<브랜치명>
```

이미 로컬 branch가 있다면:

```powershell
git switch <브랜치명>
git pull --ff-only
```

`git pull --ff-only`는 예상하지 않은 자동 merge를 방지합니다.

## 3. Codex 실행 위치

Codex는 반드시 저장소 최상위 폴더에서 실행하거나, Codex Desktop에서 해당 폴더를 workspace로 엽니다.

```powershell
cd C:\작업경로\Freelance-Ops-Agent
codex
```

IntelliJ가 `apps/backend`만 열려 있더라도 Codex는 가능하면 repository root를 열어야 합니다. 그래야 다음 파일을 모두 볼 수 있습니다.

```text
AGENTS.md
docs/V2_SPECIFICATION.md
docs/STATUS.md
docs/adr/
apps/backend
apps/agent
apps/web
infra
contracts
```

## 4. 다른 PC에서 처음 Codex에 입력할 명령

다음 prompt를 그대로 재사용하면 됩니다.

```text
이 저장소의 이전 작업을 이어서 진행하려고 합니다.

먼저 다음 순서로 문서를 읽으세요.

1. AGENTS.md
2. README.md
3. docs/V2_SPECIFICATION.md
4. docs/STATUS.md
5. docs/adr/ 아래의 Accepted ADR 전체

그다음 아래 내용을 확인하세요.

- 현재 Git branch
- git status
- 최근 commit 5개
- 현재 구현된 파일 구조
- STATUS에 기록된 완료 작업과 다음 작업
- 문서와 실제 코드 사이의 불일치

아직 파일을 수정하지 말고 다음 내용만 먼저 보고하세요.

1. 현재 프로젝트 상태
2. 확정된 아키텍처 결정
3. 마지막 작업에서 완료된 내용
4. 지금 이어서 해야 할 최우선 작업
5. 예상 변경 파일
6. 실행할 검증 방법
7. 발견한 blocker 또는 문서 충돌
```

Codex가 상태를 정확히 파악한 것을 확인한 뒤 작업을 요청합니다.

```text
확인했습니다.

docs/STATUS.md에 기록된 다음 작업 중 첫 번째 항목을 구현하세요.
AGENTS.md와 Accepted ADR을 준수하고 기존 사용자 변경을 보존하세요.

작업 완료 후:

1. 관련 테스트와 정적 검사를 실행하세요.
2. git diff를 검토하세요.
3. docs/STATUS.md를 갱신하세요.
4. 민감 정보가 없는지 검사하세요.
5. commit과 push는 하지 말고 결과를 보고하세요.
```

- 변경 후 ./gradlew test를 실행하세요.

## 6. 매번 사용할 짧은 명령

문서 체계가 안정된 후에는 다음 정도로 줄일 수 있습니다.

```text
AGENTS.md와 docs/STATUS.md를 읽고,
관련 V2 명세와 Accepted ADR을 확인한 다음
STATUS의 최우선 다음 작업을 이어서 수행하세요.

먼저 Git 상태와 실제 구현이 STATUS와 일치하는지 확인하세요.
완료 후 테스트, diff 검토, STATUS 갱신까지 수행하되
commit과 push는 하지 마세요.
```

## 7. 두 PC에서 동시에 작업할 경우

동시에 같은 branch를 수정하면 충돌 가능성이 높습니다. 작업별 branch를 분리하세요.

```text
codex/v2-spring-foundation
codex/v2-agent-foundation
codex/v2-infrastructure
codex/v2-rbac
```

예:

```powershell
git switch -c codex/v2-agent-foundation
git push -u origin codex/v2-agent-foundation
```

다른 PC에서는:

```powershell
git fetch origin
git switch --track origin/codex/v2-agent-foundation
```

동시에 작업하지 않고 장소만 이동하는 경우에는 같은 feature branch를 사용해도 됩니다.

## 8. Git으로 전달되지 않는 것

다음 항목은 Git에 push해도 다른 PC로 전달되지 않습니다.

- `.env`
- OpenAI/Gemini API key
- Docker volume
- 로컬 PostgreSQL 데이터
- IDE 설정 일부
- 설치된 Java, Python, Node
- commit하지 않은 변경
- `git stash`

각 PC에는 별도로 환경변수를 설정해야 합니다.

```text
.env.example     Git에 포함
.env             각 PC에서 별도 생성, Git 제외
```

DB 상태를 동일하게 유지하려면 로컬 DB 자체를 복사하기보다 다음을 Git으로 관리하는 것이 좋습니다.

- Flyway migration
- seed script
- 익명화된 fixture
- evaluation dataset
- 재현 가능한 초기화 명령

## 핵심 작업 루틴

```text
PC A
작업
→ 테스트
→ STATUS 갱신
→ commit
→ push

PC B
fetch
→ branch 전환
→ pull --ff-only
→ Codex 실행
→ AGENTS/STATUS/ADR 확인
→ 작업 계속
```

가장 중요한 명령은 이것입니다.

```text
AGENTS.md와 docs/STATUS.md를 먼저 읽고,
관련 V2 명세와 Accepted ADR을 확인한 뒤
현재 Git 상태와 문서가 일치하는지 검증하고 작업을 이어가세요.
```

이 명령과 최신 Git branch만 있으면 이전 Codex 대화가 없어도 상당히 안정적으로 작업을 계속할 수 있습니다.
