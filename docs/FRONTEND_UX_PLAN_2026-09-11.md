# 반응형 프론트엔드 UX 개선 계획

목표: 기존 Figma 기반 디자인과 현재 시스템의 권한·저장·분석 흐름을 유지하면서 필요한 정보를 찾고 다음 작업으로 이동하는 수고를 줄인다.

## 구현 범위

1. 프로젝트 탐색: 전체 단계 목록을 제공하고 작은 화면에서는 목록을 기본으로 표시한다. 상세 화면에 다녀와도 검색·보기·정렬 조건을 유지한다. 검색 초기화와 결과 안내를 제공한다.
2. 문의 등록: 프로젝트 이름과 문의 원문을 먼저 입력하고 고객·예산·일정은 선택 입력으로 구분한다. 잘못된 입력은 해당 위치에서 바로 수정하도록 안내한다.
3. 반응형·접근성: 모바일 터치 영역과 입력 글자 크기, 긴 제목과 작업 버튼 배치, 대화상자의 키보드 포커스를 점검한다.
4. 검증: 기존 자동 검사와 빌드, 주요 화면 크기 및 탐색·등록 동선을 확인한다. 실제 백엔드 검증 여부를 별도로 기록한다.

## 수용 기준

- 목록에 진입했을 때 특정 단계의 프로젝트만 숨겨져 보이지 않는다.
- 작은 화면에서 여러 열을 가로로 넘기지 않고 전체 프로젝트를 탐색할 수 있다.
- 검색을 초기화하는 데 한 번의 조작이면 충분하며 늦은 응답이 현재 결과를 덮어쓰지 않는다.
- 상세 화면에서 돌아오면 직전 탐색 조건이 유지된다.
- 문의 등록 시 필수 입력과 선택 입력이 명확하고 공백만으로 등록할 수 없다.
- 키보드로 대화상자를 조작할 수 있고 모바일 주요 버튼을 쉽게 누를 수 있다.
- 기존 기능과 권한 검사를 보존하고 검증 후 임시 파일·캐시를 정리한다.

## 역할

- 메인 작업: 탐색 상태, 검색, 화면 이동, 통합 검증
- UX 검토 에이전트: 문의 등록 흐름과 대화상자 입력
- 반응형 검토 에이전트: 기존 CSS의 모바일·접근성 개선

## 구현 결과

- 전체 단계 목록을 기본 필터로 추가했다. 820px 이하에서는 목록을 기본으로 사용하고, 사용자가 선택한 보기 방식은 화면 크기가 바뀌어도 유지한다.
- 모바일 단계 필터를 한 줄 선택 메뉴로 제공하고, 제목·요약·카드 간격을 줄여 프로젝트 탐색에 필요한 스크롤을 줄였다.
- 검색은 입력 후 300ms에 자동 반영한다. 검색 중 안내와 검색·필터 초기화를 제공하며 이전 요청의 늦은 응답을 무시한다.
- 상세 화면을 오가도 보드의 검색·필터·정렬·보기 상태를 유지한다. 돌아올 때 직전 카드에 초점과 스크롤 위치를 복원한다. 작업 공간 전환 시에는 탐색 상태를 분리한다.
- 검색 결과는 최신 프로젝트 객체를 사용하고 프로젝트 변경 시 다시 검색한다. 수정 전 정보나 삭제된 항목이 남지 않도록 보완했다.
- 요약 숫자에서 전체·견적 작성·완료 목록으로 직접 이동한다. 실제 미작성 여부를 알 수 없는 ‘회고 필요’는 ‘완료 프로젝트’로 변경했다.
- 문의 등록은 이름과 원문을 먼저 입력한다. 고객·통화·일정·예산은 선택 정보로 접고, 접힌 값도 저장한다. 공백 입력·예산 역전 오류는 해당 필드로 초점을 이동한다.
- 신규·수정·삭제 대화상자의 초점 제어를 통일했다. 접힌 선택 입력은 Tab 순서에서 제외하고, 저장 중 모든 컨트롤이 비활성화돼도 Tab이 배경으로 빠지지 않도록 처리했다.
- 모바일 주요 조작 영역을 44px로 확대하고 입력 글씨는 16px로 맞췄다. 복수 작업 공간 헤더, 긴 제목, 수정 양식과 소개 페이지 제목·로그인 버튼을 보완했다.

## 브라우저 검수

별도 로컬 테스트 API와 가상 계정으로 확인했다. 실제 고객 자료를 사용하거나 운영 데이터를 변경하지 않았다.

- 320px·390px 모바일, 820px 태블릿, 1440px 데스크톱에서 주요 레이아웃과 페이지 가로 넘침 없음 확인
- 모바일 전체 목록 기본값, 완료 요약 바로가기, 다크 모드, 복수 작업 공간 헤더 확인
- 서로 다른 단계의 자동 검색 결과, 초기화, 정렬, 상세 진입 후 브라우저 뒤로 가기의 조건·초점 복원 확인
- 검색한 프로젝트의 제목을 상세 화면에서 변경한 뒤 최신 제목 반영 확인
- 신규 문의의 공백 검증, 저장 실패 시 입력 유지, 선택 정보 없는 기본 등록 확인
- 선택 정보를 접은 상태의 USD·예산 저장, 예산 역전 오류 시 자동 펼침과 필드 초점 확인
- 신규 문의의 마지막 버튼에서 Tab 순환, 삭제창의 Shift+Tab 순환·Escape·배경 스크롤 제한 확인

## 검증 범위와 한계

Node 22.23.2에서 `npm run preview:check`를 통과했다: 타입 검사, 테스트 45개, ESLint, 프로덕션 빌드(`/`, `/workspace`, `/proposal/[token]`). `git diff --check`도 통과했다. 구현과 로컬 검증을 완료했다.

실제 Spring 서버·AI 실행·고객 제안 승인까지의 통합 검증 및 사용자 대상 사용성 평가는 이번 검수에 포함하지 않았다. 클릭 수나 성과 향상을 실사용 데이터로 측정한 것은 아니다.

후속 통합 작업에서 실제 Spring·Agent·PostgreSQL 및 공개 제안서 응답을 검증했다. 결과와 환경 복구 사항은 [실제 서버 통합 검증](FRONTEND_INTEGRATION_2026-09-11.md)에 기록했다. 사용자 대상 사용성 평가와 성과 측정은 여전히 별도다.

탐색 조건은 현재 작업 공간을 이용하는 동안 유지하며 새로고침까지 보존하지 않는다. 신규 문의를 명시적으로 닫으면 입력이 사라지는 기존 동작은 유지한다. 이번 변경은 커밋·푸시·배포하지 않았다.
