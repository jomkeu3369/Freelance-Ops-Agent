# 펫과 대화하며 완성하는 견적 — 개편안

상태: 시안 승인 후 실제 대화 기능 구현. 아래 HTML 시안은 참고용이며 운영 적용은 별도 배포한다.

## 구현된 실행 계약

- 설정 조회·수정: `GET/PUT /api/v2/workspaces/{workspaceId}/projects/{projectId}/pet-conversation`. 본인 활성 펫 최대 3명과 설정 버전을 저장하며 활성 실행 중에는 변경을 거부한다.
- 대화 제출: 기존 실행 시작 API의 `conversation: {settingsVersion, recipientPetId}`. Backend가 사용자별 최근 6턴·등록 단가·반영한 초안을 해석한다. Agent는 기존 예산 원장과 선택 모델을 이용하여 최대 3회의 순차 공개 응답을 생성한다. 토론 끄기·지목 응답·기본 AI 모드는 1회다.
- `pet.message.started/completed` 이벤트와 `result.petMessages`에 작성자 프로필·답글 대상·실제 참고 자료 스냅샷을 저장한다. 완료된 발화는 취소와 재연결 뒤에도 복원하며 미완성 발화를 가짜 응답으로 만들지 않는다. 토큰 단위 스트리밍은 제공하지 않는다.
- 초안 반영: `POST .../pet-conversation/draft`에 `runId, expectedVersion`만 보낸다. 서버가 본인의 완료/부분 완료 실행에서 제안 원본을 읽는다. 대화 초안 반영은 견적 문서의 저장·확정·발행과 별개이며 기존 검토 단계를 거친다.
- `V52`는 개인별 프로젝트 설정과 대화 턴을 추가한다. 기존 단일 동료 선택과 과거 분석 결과는 유지한다. Agent → Backend(V52 포함) → Frontend 순으로 배포한다. Frontend만 배포하면 이전 Backend에서 설정 조회가 실패하여 새 대화 제출이 차단된다.
- 긴 문맥은 발췌임을 명시하여 전달한다. 대화 제안은 권장 초안 하나로 제한하며, 추가 시나리오 비교는 기존 견적 검토에서 수행한다. 모델은 금액을 확정하지 않으며 미정 단가는 서버 미리보기에서 제외한다.
- 되돌릴 때는 우선 Frontend를 이전 버전으로 되돌려 새 대화 진입을 중지한다. 새 발화를 읽을 수 있도록 Backend·Agent의 추가 응답 계약과 V52 데이터는 유지한다. 저장된 새 결과가 있는 상태에서 Agent까지 이전 계약으로 되돌리지는 않는다.

## 목표

자연어 요구사항을 펫 1~3명과 함께 이야기하며 근거 있는 견적으로 완성한다. 펫은 결과 화면의 장식이나 견적안별 고정 역할을 넘어, 같은 대화 안에서 사용자에게 질문하고 다른 펫의 주장에 근거와 대안을 붙인다. 사용자는 중간에 개입하고 최종 범위를 결정한다.

말투는 장난스럽게 티격태격하되 근거를 분명하게 한다. 예산·일정·범위가 충돌할 때만 짧게 의견을 주고받는다. 의견이 같으면 억지로 반대하거나 싸움을 만들지 않는다. 결정이 필요한 시점에는 사용자의 답을 기다린다.

## 현재 구현과 차이

- `CustomAgentPetService.Collection.selectedPetId`와 `custom_agent_pet_selection`은 개인 펫 한 명만 선택한다. `runtimeProfiles`도 최대 한 명을 반환한다.
- 실행 계약의 `petProfiles`는 최대 세 개지만, 기존 `slot`은 핵심안·권장안·확장안의 견적 시나리오다. 서로 다른 대화 참여자 세 명을 선택하는 계약과 구분해야 한다.
- `AgentChat`은 사용자와 에이전트의 대화·실행 결과를 표시한다. 펫별 발화와 서로의 발화에 대한 답글, 토론 종료 조건은 없다.
- `PetWorkspace`는 실행 스냅샷과 부서 결과를 보여준다. 현재 문구와 아바타를 바꾸는 것만으로 실제 펫 대화가 구현되지는 않는다.
- `AnalysisStep`의 ‘작업 자세히 보기’는 펫 결과, 진행 단계, 활동 기록을 큰 패널에 모은다. 사용자에게 필요한 질문·오류·결정이 대화와 분리되어 있다.

## 새 화면

검토용 시안: [대화 중심 작업 공간](../prototypes/pet-conversation-workflow/index.html).

1. 메인은 ‘사용자 + 참여 펫’의 한 대화다. 펫마다 이름·외형·검토 중점·답글 대상을 표시한다. 특정 펫에게 질문하거나 모두에게 말할 수 있다.
2. 상단에서 참여 펫을 1~3명 선택한다. 선택은 다음 사용자 메시지부터 적용하고 과거 대화의 작성자를 바꾸지 않는다. 실행 중 조합을 바꾸면 현재 응답을 먼저 멈추고 적용한다.
3. ‘펫과 대화’를 끄면 기본 AI 대화로 이어간다. 펫 토론과 향후 펫 발화를 중지하고 대화·요구사항·견적 초안을 보존한다. 다시 켜면 마지막 조합을 복원한다.
4. ‘펫끼리 토론’만 끌 수도 있다. 펫 대화는 유지하되 대표 펫 또는 지목한 펫이 간결하게 답한다.
5. 옆에는 확인된 요구사항, 아직 결정할 질문, 견적 초안만 보여준다. 모바일에서는 같은 내용을 대화 아래에서 확인한다. 근거는 해당 발화·항목에서 연다.
6. 펫의 제안은 즉시 확정 범위가 되지 않는다. 사용자가 확인한 변경만 초안에 반영한다. 예산 초과와 단가 미정은 수치와 상태로 표시한다.
7. 진행 상태·중단·오류·재시도는 대화 안에서 설명한다. ‘작업 자세히 보기’는 메인 동작에서 제거하고, 상세 이벤트는 접힌 ‘실행 기록’으로 유지한다.
8. ‘이야기하며 정리 → 견적 검토 → 전달’의 사용자 흐름을 유지한다. 새 발화마다 전체 프로젝트 분석을 처음부터 반복하지 않는다.

## 검토용 시안의 동작과 한계

- 최대 세 명 선택, 선택 변경, 특정 상대 지정, 펫 대화·토론 끄기, 예시 발화의 순차 표시, 중간 개입과 중지, 제안 반영/거절, 근거 확인, 견적 검토, 중단 상태를 누를 수 있다.
- 모든 대화와 공수·단가는 가상 예시다. 응답은 미리 작성한 예시이며 사용자가 입력한 자연어를 실제로 분석하지 않는다. AI·업무 API·DB에 연결하지 않고 키나 로그인 정보를 읽지 않는다.
- 예시 견적은 46시간 × 50,000원에 부가세 10%를 더한 2,530,000원이다. 결제 연동 예시 12시간을 포함하면 3,190,000원이다. 공수는 가정이고 금액만 코드로 계산한다.
- ‘초안에 반영’은 메모리 상태만 바꾼다. 저장·발행 기능으로 안내하지 않는다. 실제 펫은 기존 라이브러리의 생성된 외형을 그대로 사용한다.

## 실제 기능 연결 설계

### 참여자와 설정

프로젝트별 대화 설정에 `petMode`, `debateEnabled`, 순서가 있는 `participantPetIds`를 저장한다. 저장 API는 사용자·워크스페이스·프로젝트 권한과 본인 소유의 활성 펫을 확인하고 중복·네 명 이상·수정 충돌을 거부한다. 켜진 상태에서 빈 팀을 허용하지 않는다. 기존 개인 동료 선택은 첫 참여자로 이관하며 기존 API와 실행 이력은 유지한다.

각 사용자 메시지의 실행을 접수할 때 서버가 참여자 프로필과 설정 버전을 고정한다. 진행 중 이름·외형·선호가 바뀌거나 펫을 보관해도 과거 발화가 바뀌지 않는다. 시나리오용 `slot`을 대화 작성자 ID로 사용하지 않고 `speakerPetId`로 구분한다.

### 대화와 실시간 표시

현재 실행 이벤트·대화 이력에 공개 발화 계약을 추가한다. 예: `messageId`, `turnId`, `speakerPetId`, `replyToMessageId`, `text`, `evidenceRefs`, `proposedChangeId`, `sequence`. 완료된 발화는 서버에 보관하고 SSE 재연결 시 ID·순서로 중복을 제거한다. 유실된 완료 발화는 이력 조회로 복구한다.

선택된 모델은 역할별 공개 발화를 생성한다. 실제로 별도 실행하지 않은 펫을 독립 모델이나 독립 검증자로 표시하지 않는다. 내부 추론 과정 대신 사용자에게 필요한 제안·근거·불확실성·반론을 전달한다. 기존 부서 진행 이벤트를 가짜 펫 발화로 바꾸거나 최종 답을 타이핑 효과로 잘라 실시간 AI 스트림이라고 안내하지 않는다.

첫 답변에 필요한 문맥은 현재 요구사항·최근 결정·등록 단가·검증 가능한 자료다. 발화에는 실제 참조 가능한 근거 ID를 붙인다. 근거 없는 공수는 가정으로 표시하며, 서로 다른 펫의 동의 자체를 근거로 취급하지 않는다.

### 토론과 사용자 개입

토론은 현재 요청의 범위에서 최대 세 명이 짧게 의견을 주고받고 사용자에게 선택지를 돌려준다. 기본 상한은 사용자 메시지당 펫 발화 세 개와 짧은 정리 한 개다. 더 논의하려면 사용자 메시지가 필요하다. 무한 자동 대화·새 작업·새 모델 실행을 펫 성격으로 허용하지 않는다.

‘잠깐 멈춰’는 기존 취소 계약에 연결한다. ‘말 끊고 보내기’는 이전 실행의 취소/종료를 확인한 뒤 같은 대화에 새 메시지를 접수한다. 취소가 확인되지 않으면 새 실행을 중복 시작하지 않고 입력을 보존한다. SSE가 끊겼다는 이유만으로 취소나 새 실행을 추정하지 않는다.

펫 대화 끄기와 팀 변경도 현재 실행 중지를 확인한 뒤 다음 턴에 적용한다. 꺼진 상태에서는 펫 발화를 추가로 생성하지 않는다. 과거 발화·완료된 변경·초안은 보존한다.

### 견적과 근거

대화는 하나의 작업 견적을 점진적으로 수정한다. 세 명의 펫을 견적 세 안에 강제로 하나씩 대응시키지 않는다. 핵심·권장·확장 비교가 필요할 때만 비교안을 별도로 요청한다.

펫은 범위·공수·가정·질문과 변경안을 제안한다. 금액·세금·합계는 기존 단가/서버 계산 계약을 따른다. 미정 단가는 0원이나 무료로 채우지 않는다. 변경안에는 대상 견적 버전과 적용 전후 차이를 붙이고, 사용자가 수락할 때만 적용한다. 초안 저장·확정·발행·공유 권한은 기존 계약을 유지한다.

## 구현 순서와 검증

1. 대화 흐름과 정보 배치를 시안으로 확인한다.
2. 프로젝트별 참여자 1~3명·끄기 설정과 실행 스냅샷을 Backend/DB/계약에 추가한다. 이전 단일 선택과 이력을 호환 검증한다.
3. Agent의 근거 포함 공개 발화·상한 있는 토론·취소를 기존 예산 원장과 연결한다. 실제 이벤트 저장·복구를 확인한다.
4. 프런트엔드의 이름별 발화·답글·근거·중간 개입·초안 변경 승인에 연결하고 별도 작업 상세 패널을 정리한다.
5. 권한 회수, 팀 변경, 취소 실패, 부분 응답, 재연결, 중복 재시도, 미정 단가, 수정 충돌, 한영·모바일·키보드·동작 줄이기를 검사한다.
6. 합성 시나리오 결과와 실제 모델·DB 통합 결과를 구분해 PR에 기록하고 미리보기 확인 후 운영에 반영한다.

모든 펫 발화는 기존 실행의 호출·토큰·시간·금액 한도를 공유한다. 펫 수만큼 예산을 새로 부여하거나 자동 폴백하지 않는다. 사용자 메시지 제출 전에 선택된 모델과 사용량/비용을 확인할 수 있게 유지한다.
