# 개인 AI 연결

2026-10-16 코드 기준. 개인 키의 실제 이용 권한·잔액·생성 품질은 제공사 계정에서 확인한다.

## 등록과 실행

1. 설정의 AI 연결에서 OpenAI 모델과 API 키를 선택한다. 서버가 공식 모델 조회 API로 접근을 확인한 뒤 암호화해 저장한다.
2. 같은 제공사의 키를 다시 등록하면 연결 ID를 유지하면서 키·모델을 교체한다. 검증에 실패하면 기존 연결을 보존한다. 저장한 키는 끝 네 자리만 표시한다.
3. 분석을 보내기 전에 기본 제공 AI 또는 개인 연결을 명시한다. 개인 연결 실패 시 기본 키나 다른 모델로 자동 전환하지 않는다.
4. 개인 연결로 시작한 실행은 같은 사용자만 재개할 수 있다. 연결을 삭제하거나 권한을 회수하면 다음 호출·재개가 차단된다. 이미 제공사에 전송된 요청은 삭제만으로 취소되지 않는다.
5. 기존 실행과 다른 모델로 연결을 교체했다면 새 분석을 시작한다.

현재 신규 호출은 **OpenAI만 지원**한다. Gemini 이름과 기존 연결 기록은 과거 데이터 호환을 위해 남아 있으며 새 등록·실행은 허용하지 않는다. `APP_BYOK_GEMINI_MODELS`를 설정해도 이 정책이 바뀌지 않는다. 허용 OpenAI 모델은 서버 카탈로그와 `APP_BYOK_OPENAI_MODELS`의 교집합이다.

## 사용량과 비용

개인 키 실행의 모델 사용료는 사용자의 제공사 계정에 청구된다. 현재 실행 경로는 로컬 라우팅과 키워드 검색을 사용하며 플랫폼 키·유료 라우팅·임베딩·웹 조사로 전환하지 않는다.

Spring은 실행별 자격 증명·모델·추론 수준·비용 안내 버전과 호출·토큰·시간 한도를 고정한다. 호출마다 현재 권한과 연결을 재검사하고, 제공사 요청 전에 보수적인 사용량을 예약한다. 재시도·재개·취소·사용량 누락으로 예산이나 마감 시간이 늘어나지 않는다. API의 미확정 토큰은 실제 청구량이 아닌 예약 상한일 수 있다.

신규 기본 제공 AI는 USD 예약·정산 원장을 사용한다. 이전 월간 횟수·주간 고정 크레딧 잔액을 새 실행의 사용 가능량으로 표시하지 않는다. 상세 응답과 한도는 [사용량 API](../testing/platform-usage-api-2026-10-05.md)를 따른다. 별도 견적 가정 생성과 유료 동료 생성은 현재 차단돼 있다.

## 공개 API와 권한

경로는 `/api/v2/workspaces/{workspaceId}/ai-connections`다. 모든 호출은 현재 로그인·멤버십과 `agent.run`을 확인하며 같은 워크스페이스의 다른 Owner도 본인 소유가 아닌 키를 사용할 수 없다.

| 호출              | 계약                                                         |
| ----------------- | ------------------------------------------------------------ |
| GET               | 저장 기능 사용 가능 여부, 제공사별 허용 모델, 본인 연결 목록 |
| PUT `/{provider}` | `{model, apiKey}` → 연결 ID·제공사·모델·마스킹·갱신 시각     |
| DELETE `/{id}`    | 본인 연결 삭제, 성공 204                                     |

`modelSelection.credentialId`가 없으면 기본 제공 AI, UUID이면 해당 개인 연결을 사용한다. 키 원문은 실행 요청·응답·로그·발송 대기 명령·체크포인트에 저장하지 않는다. Spring 내부 자격 증명 API는 호출 직전에만 키를 해결한다.

## 운영과 복구

- `APP_BYOK_ENCRYPTION_KEY`는 32바이트를 Base64로 인코딩한 AES-GCM 키다. [최초 생성 스크립트](../../infra/scripts/ensure-byok-key.sh)는 서버의 비공개 환경 파일에서 기존 키를 보존하며 잘못되거나 중복된 값은 덮어쓰지 않고 거부한다.
- DB를 복원할 때는 **동일한 암호화 키**가 필요하다. DB 덤프와 별도 접근 권한으로 보관한다. 키를 잃으면 기존 연결을 복호화할 수 없어 재등록해야 한다.
- 재배포·롤백은 키를 교체하지 않는다. 키를 순환하려면 이전 키로 복호화하고 새 키로 재암호화하는 별도 절차가 필요하다.
- 등록 확인은 모델 접근 검사이며 생성 성공이나 잔액을 보장하지 않는다. 오류에 키 원문이나 거부된 입력을 남기지 않는다.

## 검증 근거

초기 연결 기능은 [2026-09-12 검증 기록](../testing/byok-connections-2026-09-12.md)과 [PR #36](https://github.com/jomkeu3369/Freelance-Ops-Agent/pull/36), 호출 예산·사용량 통합은 [2026-10-05 기록](../testing/cloud-feature-integration-2026-10-05.md), 현재 배포와 회귀 검사는 [제품 근거](../portfolio/product-evidence.md)에 연결한다. 합성 키·가상 응답으로 수행한 검사를 실제 개인 키의 과금·잔액·생성 품질 검증으로 해석하지 않는다.
