# 나만의 동료: 3차 사용·검증 안내

프로젝트의 **새 분석 준비 → 나만의 작은 동료 만들기**에서 사용한다. 진행 중이거나 완료된 실행을 수정하는 화면이 아니다.

1. 핵심안·권장안·확장안 중 꾸밀 동료를 선택한다.
2. 이름(20자), 동물(거북이/부엉이/고양이), 색상 6종, 장식 4종과 말투·판단 성향을 고른다.
3. 또는 한 문장으로 설명하고 **AI로 외형·성향 생성**을 누른다. 분석 시작 영역에서 선택한 기본 제공 AI/BYOK 모델을 사용한다.
4. 생성 결과는 지원하는 SVG 조합의 미리보기다. 자유 형태 이미지 생성이나 파일 업로드는 제공하지 않는다. 대기·작업·질문 동작을 확인하고 **이 동료 저장**으로 확정한다.
5. 다음 분석부터 저장한 프로필을 사용한다. 미저장 입력은 분석에 반영하지 않는다. 다른 동료 선택 전에는 저장하거나 수정 취소한다.

수익/관계, 빠른 납품/완성도, 보수적/도전적 제안은 실제 범위·납품 단계·조건·트레이드오프의 우선순위에 전달된다. 핵심/권장/확장안의 의미와 근거·권한·금액 계산은 그대로 유지한다. 성향 변경만으로 결과 품질이나 수익이 보장되지는 않는다.

## API·권한 계약

- `GET /api/v2/workspaces/{workspaceId}/pets`: 본인의 세 프로필(미저장 슬롯은 기본값).
- `PUT /api/v2/workspaces/{workspaceId}/pets`: 닫힌 `PetProfile` DTO 한 개를 검증하여 슬롯별 저장. 이름·외형·성향 외 필드로 권한이나 도구를 변경할 수 없다.
- `POST /api/v2/workspaces/{workspaceId}/projects/{projectId}/pet-generations`: `{slot, description, modelSelection}` → `{runId, profile, provider, model, inputTokens, outputTokens}`. 모델 선택은 기존 `ModelSelection`, 설명은 최대 500자.
- 모두 현재 membership과 `agent.run`을 요구한다. 생성은 `project.read` 및 같은 workspace의 삭제 중이 아닌 프로젝트를 추가 확인한다. 다른 Owner도 본인 프로필만 수정한다.
- 개인 키는 기존 BYOK 계약을 따른다. 생성 결과와 일반 프로필 DTO에 키 원문이 없다.
- 400/422: 잘못된 입력, 403/404: 권한·범위, 429: 하루 생성 상한, 502: 생성 실패. 실패는 자동 재시도하지 않는다.
- Spring→Agent 계약은 `agent-internal-api` 0.6.0. 기존 실행에는 `petProfiles`가 없어도 호환된다.

## 비용·운영

이미지 저장소나 새 운영 비밀값은 필요 없다. V34 migration에 개인 프로필과 생성 요청 이력이 추가된다. Spring이 프로필 스냅샷을 outbox 실행 요청에 저장하고 Agent가 실행 metadata/checkpoint에 보존한다. 현재 프로필을 바꿔도 과거 의견의 캐릭터가 바뀌지 않는다.

생성은 요청당 모델 호출 1회, 출력 최대 1,000 token, Agent 30초로 제한한다. 사용자/workspace별 UTC 하루 20회이며 실패·진행 중 요청도 포함한다. 분산 서버에서도 DB transaction lock으로 한도를 예약한다. 전역 Gateway·API rate limit과 모델 allowlist도 적용된다. 개인 모델 실패 시 기본 제공 모델로 전환하지 않는다.

`app.pet_generation`은 요청 ID·workspace·사용자·provider/model·연결 ID·상태·확인된 입력/출력 token을 기록한다. 자연어 설명과 자격 증명은 저장하지 않는다. 실패 시 확인할 수 없는 사용량은 NULL이며 무료 또는 0 token이라는 뜻이 아니다. 견적 분석 실행 원장과 별도 기록이고, 실제 청구액은 제공사에서 확인한다. 완료 token 수는 생성 미리보기에서 표시한다.

## 검증과 미검증

합성 공급자와 로컬 API fixture로 생성→미리보기→명시적 저장→새로고침 유지, 생성 실패 보존, 기본 복원, 모바일·다크 모드와 실제 실패 상태 표시를 확인한다. 백엔드 CI는 PostgreSQL에서 소유자/workspace 격리, 권한 회수, 일일 한도, 생성 실패·usage 기록과 미리보기 미저장을 검증한다.

실제 개인 키의 제공사 생성, 미적 품질, 성향별 결과 유용성과 실제 휴대폰 사용감은 사용자 검수 항목이다. 합성 브라우저 fixture는 배포 코드에 포함하지 않는다.
