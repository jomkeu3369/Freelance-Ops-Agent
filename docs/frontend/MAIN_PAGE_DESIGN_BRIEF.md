# Freelance Ops Agent 메인 페이지 디자인 브리프

## 1. 이 문서의 목적

이 문서는 웹 디자이너가 Freelance Ops Agent의 **메인 랜딩 페이지**를 제작할 때 참고하는 문서입니다.

이번 협업에서 디자이너가 제작하는 범위는 1920×1080 기준의 메인 페이지 시안입니다. 디자이너가 반응형 화면이나 애플리케이션 내부 화면까지 제작하지 않습니다. 디자이너의 시안을 받은 뒤, Codex가 다음 작업을 이어서 진행합니다.

- 메인 페이지를 React·TypeScript로 변환
- 1440px, 1024px, 768px, 390px 기준 반응형 적용
- 대시보드·요구사항 분석·견적·프로젝트 화면 제작
- loading, error, empty, focus 등의 UI 상태 구현
- Spring Boot API와 연결

따라서 디자이너는 데스크톱 메인 페이지의 시각적 방향과 핵심 화면 구성을 완성하는 데 집중합니다.

## 2. 선택한 레퍼런스

[Pinterest 레퍼런스 시안](https://kr.pinterest.com/pin/926052742129752155/)

이 시안에서 참고할 부분은 다음과 같습니다.

- 검은색에 가까운 넓은 배경
- 화면 중앙에 배치된 짧고 강한 Hero 문구
- 주황색 발광 링과 부드러운 조명
- Hero 아래에서 떠오르는 제품 화면
- 제품을 신비한 장식이 아니라 실제 사용할 수 있는 SaaS로 보여주는 구성

브랜드명, 문구, 로고, 이미지와 UI를 그대로 복사하지 않습니다. 시안의 분위기만 참고하고 Freelance Ops Agent에 맞는 카피와 그래픽을 새로 제작합니다.

## 3. 제품을 한 문장으로 설명하면

> Freelance Ops Agent는 모호한 고객 문의를 요구사항, 확인 질문, 근거 기반 견적과 실행 가능한 프로젝트 계획으로 정리하는 프리랜서 업무 운영 플랫폼입니다.

방문자는 프리랜서 또는 소규모 에이전시입니다. 첫 화면을 본 뒤 다음 내용을 이해할 수 있어야 합니다.

> 이 서비스는 단순한 AI 챗봇이 아니라, 고객 문의를 실제 계약과 프로젝트로 이어지게 정리해 주는 도구다.

## 4. 디자인 방향

전체 분위기는 어둡고 차분하지만, 지나치게 무겁거나 복잡하지 않아야 합니다. 주황색 발광 링은 AI를 과시하기 위한 장식이 아니라, **흩어진 고객 요구사항이 하나의 실행 계획으로 정리되는 과정**을 상징합니다.

서비스가 전달해야 하는 인상은 다음과 같습니다.

- 복잡한 업무를 차분하게 정리해 주는 서비스
- 결과의 근거와 가정을 확인할 수 있는 서비스
- 프리랜서가 매일 사용할 수 있는 실용적인 서비스
- 기술적으로 세련됐지만 과장하지 않는 서비스

다음과 같은 표현은 피합니다.

- 로봇, 뇌, 가상 비서처럼 보이는 흔한 AI 이미지
- “100% 자동화”처럼 검증할 수 없는 주장
- 네온과 3D 장식이 콘텐츠보다 앞서는 화면
- 일반적인 프로젝트 관리 SaaS와 구분되지 않는 통계 카드 중심 화면
- 실제 고객 개인정보, 회사 로고, 계약 금액처럼 보이는 자료

## 5. 메인 페이지에서 사용할 기본 카피

### Hero

작은 상단 문구:

`AI-POWERED FREELANCE OPERATIONS`

메인 제목:

> 모호한 고객 문의를, 실행 가능한 프로젝트로.

설명:

> 고객의 요구사항을 분석하고, 필요한 질문과 근거를 정리해 견적·제안서·업무 계획으로 연결합니다.

버튼:

- 주요 버튼: `요구사항 분석 시작하기`
- 보조 버튼: `작동 방식 보기`

회원가입이나 무료 플랜이 아직 확정되지 않은 상태라면 주요 버튼은 `데모 흐름 보기`로 바꿀 수 있습니다.

### 문제 제시

섹션 제목:

> 프리랜서의 가장 큰 비용은 일을 하는 시간이 아니라, 일을 정의하는 데 쓰입니다.

세 가지 문제를 짧은 카드로 보여줍니다.

1. **요구사항이 흩어집니다** — 메신저, 통화, 문서에 고객의 의도가 나뉩니다.
2. **견적의 근거가 약합니다** — 작업 범위와 예상 시간이 추정에 머뭅니다.
3. **다음 단계가 불분명합니다** — 질문, 제안서, 계약으로 이어지는 흐름이 끊깁니다.

### 작동 방식

섹션 제목:

> 한 번의 문의가, 검토 가능한 업무 계획이 됩니다.

네 단계로 설명합니다.

1. **문의 입력** — 고객의 원문, 파일 또는 메모를 등록합니다.
2. **요구사항 분석** — 목표, 범위, 제약과 누락 정보를 구분합니다.
3. **근거 확인** — 유사 프로젝트, 정책, 검색 자료와 가정을 나눠 확인합니다.
4. **결과 확정** — 프리랜서가 질문, WBS, 견적과 제안서를 검토한 뒤 확정합니다.

자동으로 모든 일이 끝나는 것처럼 보이지 않게 합니다. 사용자가 중간 결과를 검토하고 승인한다는 점이 보여야 합니다.

### 제품 프리뷰

섹션 제목:

> AI의 답변이 아니라, 다음 행동을 보여줍니다.

제품 프리뷰에는 실제 고객 정보가 아닌 예시 데이터를 사용합니다. 한 화면 안에 다음 세 부분을 보여주세요.

- **고객 원문**: “쇼핑몰을 새로 만들고 싶은데, 모바일도 지원되면 좋겠습니다.”
- **AI가 정리한 내용**: 목표, 대상 사용자, 기능 범위와 미확정 사항
- **다음 단계**: 확인 질문, 참고 근거와 견적 초안 상태

프리뷰에는 다음 상태를 표시합니다.

`원문` · `AI 초안` · `근거 확인 필요` · `사용자 확정`

모든 결과를 성공 상태로 표시하지 않습니다. “확인 필요”와 “가정”이 함께 보여야 이 서비스의 차별점이 전달됩니다.

### 신뢰성

섹션 제목:

> 빠른 답변보다, 설명 가능한 결과를 우선합니다.

세 가지 원칙을 보여줍니다.

- **근거** — 결과에 사용한 자료와 출처를 확인할 수 있습니다.
- **가정** — 정보가 부족한 부분은 사실처럼 숨기지 않습니다.
- **검토** — 견적과 제안서는 프리랜서가 확인한 뒤 사용합니다.

검증되지 않은 정확도, 고객 수, 절감 시간 등의 수치는 넣지 않습니다.

### 대상 사용자

섹션 제목:

> 어떤 분야의 프리랜서도, 자신의 방식으로 시작할 수 있습니다.

예시 직군은 개발자, 디자이너, 마케터, 번역가·콘텐츠 제작자, 컨설턴트입니다. 특정 직군만을 위한 서비스처럼 보이지 않게 구성합니다.

### 마지막 CTA

제목:

> 다음 고객 문의부터, 더 명확하게 시작하세요.

설명:

> 요구사항을 정리하고, 근거를 확인하고, 자신 있게 다음 단계로 이동하세요.

버튼:

`첫 요구사항 분석 시작하기`

## 6. Hero 그래픽과 이미지 방향

Hero에는 사진보다 추상 그래픽을 우선합니다. 어두운 배경 위에 주황색 또는 호박색의 얇은 빛의 궤도가 제품 프리뷰를 감싸는 형태를 권장합니다.

발광 링은 완전한 원보다 일부가 잘린 열린 아크에 가깝게 제작합니다. 제품 화면을 가리지 않으면서, 화면 아래에서 위로 떠오르는 깊이감을 만들어 주세요.

그래픽을 새로 제작할 때 참고할 키워드는 다음과 같습니다.

```text
dark graphite background, amber orange luminous orbit, soft volumetric light,
subtle glass surface, premium SaaS landing page, low contrast,
no text, no logo, no human face, no robot, no stock photo look
```

사진이 꼭 필요하다면 Hero가 아닌 보조 섹션에 사용합니다. 어두운 작업 공간, 노트북, 메모를 정리하는 손과 같은 장면을 권장하며 얼굴, 개인정보, 실제 고객 문서는 포함하지 않습니다.

원본 Pinterest 이미지나 라이선스를 확인하지 않은 에셋은 제품에 사용하지 않습니다.

## 7. 시각 요소 제안

### 색상

- 배경: `#050708`
- 카드·제품 표면: `#101316`
- 주황색 강조: `#FF7A18`
- 밝은 주황색: `#FFB15C`
- 기본 텍스트: `#F5F7FA`
- 보조 텍스트: `#98A1AA`
- 경계선: `rgba(255,255,255,0.12)`

정확한 색상은 디자이너가 조정할 수 있습니다. 단, 주황색은 AI의 신비함보다 실행 가능한 다음 단계를 강조하는 용도로 사용합니다.

### 글꼴

- 한국어: Pretendard Variable
- 영문·숫자: Geist 또는 Pretendard Variable
- Hero 제목은 크고 짧게 구성합니다.
- 설명 문장은 길게 늘이지 않고 두세 줄 안에서 읽히게 합니다.

## 8. 모션 방향

디자이너가 완성된 인터랙션을 구현할 필요는 없습니다. 다만 최종 구현자가 이해할 수 있도록 다음 연출 의도를 시안 또는 설명에 남겨주세요.

- 발광 링은 느리게 회전하거나 호흡하듯 밝기가 변합니다.
- 스크롤하면 제품 프리뷰가 아래에서 올라옵니다.
- 작동 방식의 네 단계는 순서대로 강조됩니다.
- 버튼은 색상과 밝기만 부드럽게 변합니다.

모션은 장식이 아니라 정보의 흐름을 돕는 역할이어야 합니다. 실제 애니메이션과 reduced-motion 대응은 Codex가 React 구현 단계에서 처리합니다.

## 9. 디자이너가 전달할 결과물

- 메인 페이지에 사용한 카피와 섹션 순서
- Hero 발광 링, 제품 프리뷰 등 핵심 그래픽 원본
- 사용한 폰트·아이콘·사진의 라이선스 정보
- 색상, 글꼴 크기, 여백과 주요 컴포넌트의 기준
- 필요한 경우, 모션 연출 의도를 설명한 간단한 메모

## 10. 최종 확인 기준

시안을 받은 뒤 다음 질문에 모두 “예”라고 답할 수 있어야 합니다.

- 첫 화면에서 이 서비스가 프리랜서용 도구라는 점이 보이는가?
- “고객 문의를 프로젝트로 정리한다”는 가치가 5초 안에 이해되는가?
- 고객 원문, AI 초안, 근거 확인과 사용자 확정이 구분되어 보이는가?

- Pinterest 시안의 분위기는 참고했지만 브랜드와 그래픽은 독창적인가?
- Codex가 이후 반응형과 세부 화면을 확장할 수 있을 만큼 시각 규칙이 명확한가?
