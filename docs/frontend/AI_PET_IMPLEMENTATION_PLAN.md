# AI 펫 작업 공간 구현 계획

> 시작: 2026-09-12 · 1차 PR #35 배포 완료 · 2차 기준 main: 62fee80
> 사용자 요청: AI_PET_WORKSPACE_PROPOSAL의 방향을 계획에 따라 실제 제품에 구현한다.

## 단계와 완료 기준

1. **설계·계약**: 현재 실행·견적 흐름을 조사하고 ADR에 펫/실행 관계, 공개 의견 계약, 계산·권한 경계와 검증 기준을 기록한다.
2. **펫의 실제 작업 표현**: 일정 거북이·근거 부엉이·수익 고양이를 프로젝트에 배치한다. 실제 실행 상태·부서·결과를 사용하며 대기/확인/실패/취소/부분 완료를 구분한다. 접기·키보드·동작 줄이기·모바일을 제공한다.
3. **서로 다른 의견**: 기존 bounded 분석의 핵심/권장/확장안을 활용하되 성향별 제안 이유·트레이드오프를 구조화 출력에 추가한다. 별도 Agent 3개나 추가 모델 호출은 기본 경로에 만들지 않는다. 과거 실행에 없는 의견을 만들어 표시하지 않는다.
4. **변경 미리보기·견적 반영**: 의견별 항목과 근거를 비교하고 필요한 항목을 선택한다. Spring 계산으로 변경 전후 금액을 확인한 뒤 명시적으로 편집 초안에 반영한다. 발행 견적은 기존 revision API를 사용한다. 다른 workspace·권한 부족·오래된 응답·기존 편집 내용 손실을 방어한다.
5. **검증·첫 배포**: 상태 전이, 모델 계약, 서버 계산·권한·불변성, UI 조작·모바일을 검증한다. 한국어 START PR → CI → 저장소 규칙에 따른 병합 → CD 확인.
6. **개인 API 키(BYOK)**: 기본은 개인 소유·본인 실행만 허용한다. Spring 암호화 저장/마스킹/교체/삭제, Python 호출 시 일시적인 자격 증명 해결, 재개 시 권한·키 재검증, 공급자별 오류와 사용 원장 구분을 구현한다. 운영 암호화 키 관리와 허용 모델 계약을 먼저 확정한다.
7. **꾸미기·생성 외형**: 기본 외형을 기반으로 이름·색·액세서리·성향을 저장한다. 생성형 외형은 일관된 동작 리소스·저장 용량·생성 비용·실패 처리까지 연결한 뒤 공개한다. 자연어 성향은 구조화된 우선순위로 제한하며 권한이나 사실을 바꾸지 못한다.

첫 배포 1~5는 PR #35로 완료했다. 사용자가 2차 범위를 **설정 정리·BYOK까지**로 확정했으므로 6과 일반 설정의 수동 AI 단가 화면 제거를 진행한다. 7은 3차로 분리한다.

## 원칙

- 실제 AI 의견과 정적인 역할 소개를 구분한다. 없는 실행·근거·금액·갈등을 연출하지 않는다.
- 성향 차이는 작업 범위·우선순위·조건에 나타나야 한다. 요약은 공개 판단 설명이며 chain-of-thought가 아니다.
- 기존 모델/Tool/시간/token budget과 gateway 제한을 유지한다. 합의가 있으면 반론을 만들지 않는다.
- 개인 키를 프론트 영구 저장소·일반 DTO 로그·checkpoint에 포함하지 않는다.
- 사용자 검수 항목: 펫의 매력/집중 방해 여부, 의견 선택의 유용성, 실제 휴대폰 사용감. 자동 검증은 실제 전환율 개선을 입증하지 않는다.
