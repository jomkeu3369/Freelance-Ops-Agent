# 나만의 작은 동료

## 사용 방법

로그인 뒤 프로젝트의 **함께할 펫**을 열면 저장한 동료를 카드로 비교할 수 있다. 카드 전체를 누르면 다음 작업에 사용할 동료를 선택한다. 선택 상태는 테두리와 체크로 표시한다. 데스크톱은 3열이며 화면이 좁아지면 열 수를 줄인다.

**펫 만들기**에서 원하는 동물과 성격을 설명한 뒤 **펫 생성하기**를 누른다. 실제 모델이 외형과 성향을 만드는 동안 로딩 화면을 보여 준다. 결과를 확인하고 **이 펫과 함께하기**를 누르면 저장·선택한 뒤 목록으로 돌아간다. 생성·저장 버튼은 같은 하단 위치에 있다. **설명 수정**은 입력을 유지한 채 돌아가며, 다시 생성할 때만 새 모델 호출을 시작한다.

작성 중에는 목록을 숨긴다. **내 펫**으로 돌아가도 입력·생성 결과는 유지하며 **이어서 만들기**로 복귀한다. 초안이 있으면 다른 동료를 선택하거나 수정해 덮어쓸 수 없다. 목록에서 **입력 취소**를 명시적으로 누르면 초안을 지운다. 다른 동료의 보관·복원·삭제는 입력을 보존하며, 수정 중인 동료 자체를 보관하는 동작은 막는다.

OpenAI 모델이 이름·성향과 32×32 픽셀 외형을 구조화 출력으로 직접 만든다. 펭귄을 부엉이·거북이·고양이 중 하나로 치환하지 않는다. 색상 15개와 픽셀 행만 검증·보관하며, 브라우저는 이를 SVG로 그린다. 외부 이미지 주소나 임의 SVG 코드는 받지 않는다. 이전 SVG 동료와 과거 실행은 그대로 읽는다. 선택·보관·복원·삭제는 모델을 호출하지 않는다.

카드 관리 메뉴의 **대화로 수정**에서 원하는 변경점을 설명한다. 이전 외형·성향을 모델에 전달하고 요청 이력은 서버가 보존한다. 요청이 여섯 개 쌓이면 **이전 요청 대신 이 설명으로 새로 정리**를 선택해야 하며, 이력을 조용히 잘라내지 않는다. 외형의 일관성과 요청 반영은 생성 결과를 보고 확인한다.

## 선택과 과거 실행

저장은 동료 하나를 선택한다. 복원만으로 선택·실행하지 않으며 선택한 동료를 보관하면 선택을 해제한다. 선택이 없으면 일반 실행 흐름을 사용한다. 개인 동료를 저장한 적 없는 기존 계정은 [세 견적안 프로필](PET_CUSTOMIZATION.md)을 호환 경로로 사용한다.

Spring은 선택한 `PetProfile`을 실행 요청에 고정한다. 재개는 원래 스냅샷을 사용하며 이름·외형·보관·삭제 변경이 과거 실행을 수정하지 않는다. 저장한 동료 수가 모델 호출이나 작업자 수를 늘리지 않는다.

## 저장과 권한

V44의 `custom_agent_pet`, `custom_agent_pet_selection`은 V34의 견적 슬롯과 별도다. V50은 `pet_generation`에 입력·생성 결과·연결 정보를 추가한다. 모든 조회·변경은 사용자와 워크스페이스를 함께 검사하고 현재 `agent.run` 권한을 재검증한다. 생성은 `project.read`와 프로젝트 상태도 검사한다. 다른 Owner도 개인 동료에 접근할 수 없다.

저장은 클라이언트의 동료·변경 UUID와 예상 revision을 사용한다. 소유자별 트랜잭션 잠금으로 수량·수정·선택을 직렬화한다. 같은 요청의 재전송은 같은 결과를 돌려주며 변경 ID 재사용·오래된 revision은 409로 거부한다. 다른 사용자 ID로 기존 데이터를 덮어쓰지 않는다.

| 제한           | 기본값 | 설정 범위                             |
| -------------- | -----: | ------------------------------------- |
| 활성 동료      |    8개 | `app.pets.max-active`, 1–24           |
| 보관 포함 저장 |   24개 | `app.pets.max-stored`, 활성 한도–100  |
| 설명           |  500자 | `app.pets.max-prompt-length`, 1–500   |
| 선호 요청 이력 |    6개 | 설명을 명시적으로 정리한 뒤 계속 수정 |

한도는 서버가 동시 요청에도 적용하고 UI에 반환한다. 보관은 활성 자리를, 삭제는 저장 자리를 확보한다. 기존 API 요청 제한도 적용한다.

## 실행에 전달하는 정보

이름·외형은 실행 명령이 아니다. `PetPreferences`의 성향·말투·중점·업무·요청 이력은 `untrusted_pet_preferences`라는 참고 데이터로 전달한다. 적용 범위는 현재 업무의 표현과 강조점이며 권한·도구·모델·자격 증명·근거·승인·예산은 서버 계약을 따른다. 문구 분리만으로 프롬프트 주입을 완전히 막는다고 주장하지 않는다.

`skillMode: AUTO`는 기존 스킬 카탈로그의 자동 선택과 연결한다. 동료 이름이나 선호 내용만으로 도구 권한을 부여하거나 별도 카탈로그를 만들지 않는다.

## API

기본 경로는 `/api/v2/workspaces/{workspaceId}`이며 응답은 `Cache-Control: no-store`를 사용한다.

| 호출                                 | 계약                                                                                |
| ------------------------------------ | ----------------------------------------------------------------------------------- |
| GET `/agent-pets`                    | 본인 모음·선택·한도·`generationMode: MODEL_PIXEL`·모델 사용 가능 여부 |
| POST `/agent-pets/generations`       | `{projectId, input: {id, mutationId, expectedRevision, description, resetPreferences}}` → 생성 작업 |
| GET `/agent-pets/generations/{id}`   | 같은 생성 ID의 상태·결과 조회. 모델을 다시 호출하지 않는다. |
| POST `/agent-pets`                   | 생성 입력에 `generationId`를 추가해 저장·선택. 서버에 보관한 결과만 사용한다. |
| POST `/agent-pets/preview`           | 기존 규칙 조합 API의 호환 경로. 새 화면은 사용하지 않는다. |
| PATCH `/agent-pets/{id}`             | `{action: SELECT/ARCHIVE/RESTORE, expectedRevision}`                                |
| DELETE `/agent-pets/{id}?revision=…` | 확인 절차를 거친 본인 보관 동료 삭제                                                |

## 비용·재시도와 운영

생성은 기본 제공 AI 금액 한도를 사용한다. `platform.ai.spend.enabled`와 해당 모델의 활성 금액 상한을 확인해 `aiGenerationAvailable`을 반환한다. 서버 설정 `app.pets.generation-model`의 기본값은 `gpt-6.1-sol`이며 OpenAI LOW로 한 번만 호출한다. 분석 화면에서 고른 모델이나 개인 키로 자동 전환하지 않는다.

사용자·전역 공통 원장에서 생성당 최대 USD 0.10을 예약한다. 입력 32,000토큰·출력 4,096토큰·모델 1회·60초 상한이며 도구 호출과 자동 재시도는 없다. 계정·워크스페이스별 UTC 하루 20건, 최근 90초 안의 진행 요청 한 건만 접수한다. 실패 요청도 일일 횟수에 포함한다. 모델을 호출하기 전에 시도를 기록하고, 응답 전에 외형까지 저장한다. 확인한 사용량만 정산하며 불명확한 호출의 예약은 유지한다.

생성 ID는 `input.mutationId`다. 같은 입력·ID의 재전송은 같은 작업을 반환하고 내용이 다르면 409로 거부한다. 상태는 `REQUESTED`, `COMPLETED`, `FAILED`, `UNKNOWN`이다. 응답 유실·화면 닫기·새로고침 뒤에는 저장한 ID를 GET으로 조회한다. 조회만으로 새 생성 비용이 발생하지 않는다. 새 요청은 사용자가 명시적으로 시작하며 실패해도 입력은 유지한다. 저장 실패의 재시도는 같은 변경 ID와 `generationId`를 사용한다.

기존 `/projects/{projectId}/pet-generations`와 Agent `/pets/generate`의 예산 차단은 유지한다. 새 경로는 Spring `/agent-pets/generations` → Agent `/pets/generate-pixel` → Spring 내부 사용량·결과 콜백이다. 위임 JWT·`X-Run-Id`·소유자·프로젝트·모델·금액 예약을 대조한다.

배포는 Agent → V50 포함 Backend → 승인된 Frontend 순서로 진행한다. 기존 API를 유지하므로 앞선 단계에서 기존 화면도 동작한다. Frontend만 있는 Vercel Preview에서는 아직 배포하지 않은 Backend 생성 API를 사용할 수 없다. 운영 반영 전 화면 검수에는 실제 모델 출력으로 만든 [검증 기록](../testing/pixel-pet-generation-2026-10-19.md)도 함께 사용한다.

검사는 선호 보존·수정·이력 한도, 계약 왕복, 참고 데이터 분리, 과거 프로필 호환, 실행 스냅샷, 저장 재전송, 소유권·동시 수량·생명주기를 다룬다. 브라우저의 합성 응답 검사는 실제 DB·배포 마이그레이션·유료 모델 품질을 대신하지 않는다. 당시 실행 결과는 [통합 검증 기록](../testing/cloud-feature-integration-2026-10-05.md), 최근 배포 근거는 [제품 근거](../portfolio/product-evidence.md)를 따른다.
