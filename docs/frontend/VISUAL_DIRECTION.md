# 화면과 문구의 시각 기준

현재 구현을 바탕으로 정리한 디자인 원칙이다. 소개 페이지·로그인 장식과 실제 업무 화면은 목적에 맞게 표현하되, 사용자가 읽고 결정하는 내용을 가리지 않는다.

## 화면별 적용 범위

| 화면          | 우선할 내용                    | 표현 기준                                                                                            |
| ------------- | ------------------------------ | ---------------------------------------------------------------------------------------------------- |
| 소개 `/`      | 해결하는 업무·결과물·시작 행동 | 라벤더·보라색, 3D 제품 예시, 스크롤·포인터 반응을 허용한다. 합성 예시를 실제 성과로 표현하지 않는다. |
| 로그인        | 계정 입력과 진입               | 배경 영상은 장식이다. 폼·오류·버튼은 충분한 대비와 접근성을 유지하고 정지 이미지를 제공한다.         |
| 프로젝트·대화 | 현재 상태·질문·결과·다음 행동  | 업무 내용이 중심이다. 내부 이벤트와 원시 상태값을 기본 화면에 나열하지 않는다.                       |
| 견적·제안     | 항목·공수·단가·근거·합계       | AI 초안과 사용자 확정을 구분하고 서버 계산 결과를 기준으로 표시한다.                                 |
| 설정          | 현재 값·이용 조건·저장         | 입력 경계·키보드 초점·실패 이유를 분명히 한다.                                                       |

개인 동료는 친근하게 표현하되 결과에 없는 대사나 완료하지 않은 작업을 만들어 표시하지 않는다. 소개용 예시와 실제 실행 상태를 구분하고 질문·근거·저장 행동을 우선한다.

## 가독성과 배치

- 본문·입력·결과를 장시간 읽을 수 있는 크기와 대비로 제공한다. 긴 한글·영문, 대체 글꼴·확대 화면에서 잘림을 확인한다.
- 제목·본문·보조 정보 사이에 위계를 두고 관련 정보는 여백과 표면 차이로 묶는다. 모든 요소를 선·그림자·발광으로 강조하지 않는다.
- 표·보드·폼은 실제 데이터와 입력값을 우선한다. 좁은 화면에서 숨겨진 조작이나 닫을 수 없는 패널을 만들지 않는다.
- 성공·경고·오류는 실제 상태를 나타내며 색상만으로 뜻을 전달하지 않는다. 키보드 초점은 배경과 구분되는 외곽선으로 표시한다.
- 업무 화면의 장식은 절제한다. 소개 화면의 광선·입체 효과를 업무 폼과 데이터 표에 일괄 적용하지 않는다.

## 움직임과 제어

동작 줄이기 환경에서도 같은 정보와 조작을 제공한다. 숨긴 탭·화면 밖의 반복 렌더링은 중단하며 입력·클릭·초점을 장식 레이어가 가로채지 않는다. 실제 화면에 없는 재생·정지·다음 단계 버튼을 안내 문서에서 약속하지 않는다.

소개 화면의 타이머·수동 선택·광선·스크롤 동작은 [구현 안내](../../frontend/features/home/README.md), 로그인은 [미디어 계약](AUTH_BACKDROP_MEDIA.md)을 기준으로 확인한다. 애니메이션의 프레임 제한은 실제 기기 FPS 보장과 구분한다.

## 문구

- `WAITING_FOR_USER`, `COMPLETED` 대신 ‘답변 대기’, ‘분석 완료’처럼 업무 언어를 사용한다.
- 구현 용어보다 사용자가 하는 행동을 설명한다. ‘오케스트레이션’ 대신 ‘분석’, ‘확인’, ‘견적 초안’을 우선한다.
- 결과와 다음 행동을 구체적으로 안내한다. 시스템이 스스로 안전성·정확성을 칭찬하는 문장은 줄인다.
- AI는 실제 역할이 있는 위치에서만 언급한다. 예상 비용·예약 금액·실제 청구와 합성 예시·실사용 결과를 구분한다.
